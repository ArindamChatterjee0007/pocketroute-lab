Guide, Privacy And Limits

A local-first field-note workbench. This release uses deterministic rules and extractive text processing, not a language model. Results require your review.

Review Before Saving

  1. Enter a note, open a UTF-8 text file, or load the clearly synthetic sample.
  2. Prepare the record. Only unambiguous lines labelled Site, Date or Ticket/Reference are extracted. Dates must use YYYY-MM-DD. Unknown or conflicting fields remain empty.
  3. Review and edit the fields and summary against the source, then confirm the review and save.
  4. Find records in the saved list. Edits require a fresh review. A stale tab cannot overwrite a more recent version.

The summary initially contains up to three complete non-metadata lines from the source. It is not a comprehensive or intelligent summary. Category suggestions are keyword-based and can be wrong or ambiguous. Edited summaries are marked user-edited.

Local Storage Is Not Encryption

Records stay in IndexedDB in this browser profile. This application does not send note text, record fields or backups to a server, analytics service or model provider. There is no account, cloud sync or team collaboration.

Local storage is unencrypted. People or software with access to the browser profile, and other scripts on the same origin, may access it. GitHub Pages project sites share an origin; use a trusted, isolated origin when self-hosting sensitive workflows. Do not treat this public demo as a secure vault or a regulated-data system.

GitHub receives normal requests for the public website assets and may log visitor metadata. After the offline cache completes, the core workflow can run without a network connection. No claim is made about security of your device or network outside this application.

Backups And Recovery

Browser cleanup, private browsing and storage eviction can erase records. Export JSON backups to a location you control. Large backups are offered as separate parts, each within the 8 MiB import limit; download and later import every part. Backup, recovery, CSV and draft files are unencrypted and may contain private information. Clearing local records does not delete exported files.

Backup import is add-only: new IDs are added, identical IDs are reported unchanged, and different content with the same ID is reported as a conflict without overwriting local data. Keep both backups and resolve differences manually. Draft exports and raw recovery files are not ordinary reviewed-record backups.

Unreadable stored rows are retained without preventing access to readable records. Storage and privacy provides a raw recovery export before destructive cleanup. This is not a guarantee of recovery from erased or physically corrupted browser storage.

CSV And Limits

CSV export uses quoted fields and prefixes spreadsheet-formula-like values with an apostrophe. This intentionally changes those CSV values to reduce formula execution risk. JSON backups preserve the original values and are the preferred round-trip format. Spreadsheet programs may still infer types such as leading-zero identifiers.

Initial limits: 100 records, 12,000 characters per source note or summary, 160 characters for title/site/reference, and an 8 MiB backup import. Labelled extraction and category rules are English-first. No OCR, voice capture, generated recommendations, autonomous actions, cloud processing or native mobile hardware benchmark is included.

Offline And Updates

The app caches only its public shell and assets. User records are stored separately. Offline-ready means the service worker controls this product page, not that every external source link is available offline. An available update waits for your confirmation; export unsaved work before reloading. Installation is browser-dependent, and ordinary browser use remains available.

Open Source And Self-Hosting

Original source and the dependency-free JavaScript core are Apache-2.0 licensed. Third-party fonts and libraries retain their own licenses. The downloadable product bundle contains the static Notes app, notices and core; serve it over HTTPS or localhost and open its notes/ path. The source repository keeps its own build/test execution on GitHub to respect the founder's development constraints. Fork owners can adapt the explicit repository guard for their own CI.
